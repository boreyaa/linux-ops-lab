### 3.3 必须建软链接的原因

代码输出的报告文件名带时间戳（`report_YYYYmmdd_HHMMSS.html`，见 `report/render.py` 第 30 行的 stamp 拼接），而 nginx 的 `index` 只找固定名 `report.html`。两者不匹配会导致访问根路径返回 404。

处理方式：每次跑完在站点目录建软链接指向最新报告。

```
cd /var/www/reports
ln -sf $(ls -t report_*.html | head -1) report.html
```

D4 配 cron 时必须把这一句一并纳入，否则每天报告更新后首页仍指向旧文件或失效。

## 四、D4 每天自动跑（2026-11-19 完成）

### 4.1 crontab 最终内容

```
30 3 * * * /bin/bash /home/bore/asminsight/scripts/run_daily.sh
```

时区已确认为 `Asia/Shanghai (CST, +0800)`，因此该行含义为北京时间每日 03:30 执行。

### 4.2 为什么用脚本而不是把命令直接塞进 crontab

文档给的方案是一行长命令。实际执行时有三件事必须同时完成：设定 PATH、跑扫描、更新软链接。三者用 `&&` 串在一行里，出错时难以定位是哪一段断的。改为脚本后每段独立，日志里能看出断点。

脚本路径：`/home/bore/asminsight/scripts/run_daily.sh`

脚本职责：

| 步骤 | 内容 |
|---|---|
| 设环境 | `PATH=/home/bore/.local/bin:/usr/local/bin:/usr/bin:/bin`，`HOME=/home/bore` |
| 记录开始 | 时间戳写入 logs/cron.log |
| 跑扫描 | `.venv/bin/python main.py --targets targets.server.yaml --out /var/www/reports/` |
| 更新软链 | 成功时 `ln -sf` 指向最新 `report_*.html` |
| 记录结束 | 时间戳与退出码写入日志 |

### 4.3 cron 的 PATH 是这个任务最大的坑

实测 cron 的执行环境 `PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`，**不含 `/home/bore/.local/bin`**。

而服务器的 nmap 是解包安装在 `~/opt/nmap`、由 `~/.local/bin/nmap` 这个包装脚本调用的（原因见第六节）。`collectors/ports.py` 第 12 行用 `shutil.which("nmap")` 查找，若 PATH 不含该目录，扫描会直接返回「nmap 未安装」，报告照常生成但内容为空。

因此脚本第一行显式导出 PATH。**这也是必须用脚本而非裸命令的直接原因。**

### 4.4 授权清单 targets.server.yaml

原 `targets.yaml` 的目标是 `192.168.88.100`（虚拟机内网地址），云服务器扫不到，且 nmap 会等到 120 秒超时。新增 `targets.server.yaml`：

```yaml
allowed_networks:
  - 127.0.0.0/8
targets:
  - 127.0.0.1
```

该文件已纳入仓库，避免服务器重新 clone 后丢失。

### 5.3 访客访问日志

目的：记录每一个外部访问者的 IP、大致归属地和时间，整理成仅本人可查看的页面。

实现链路：

| 环节 | 做法 |
|---|---|
| 数据来源 | nginx 默认 access.log（/var/log/nginx/access.log，www-data:adm 640） |
| 读取权限 | `sudo usermod -aG adm bore`，使 bore 加入 adm 组后可读 |
| 解析脚本 | scripts/gen_visitor_log.py，正则解析 combined 格式 |
| 归属地查询 | ip-api.com 免费接口，lang=zh-CN，返回国家/省/市/ISP |
| 缓存 | data/geo_cache.json，已查过的 IP 不再查询 |
| 生成频率 | cron 每小时第 5 分钟执行 |
| 输出位置 | /var/www/admin/index.html |
| 访问控制 | nginx `location /admin/` + auth_basic，密码文件 /etc/nginx/.htpasswd |

## 七、与文档不一致的两处

1. **项目放 ~/asminsight 而非 /opt/asminsight**。服务器 sudo 需密码，当前会话无法提权，/opt 归 root 不可写。影响：D4 配 cron 时路径要写全，不能依赖 /opt 约定。

2. **nmap 未预装**。D1 装机清单为 curl git vim htop，不含 nmap，而 `collectors/ports.py` 硬依赖 nmap，缺失时报「失败: nmap 未安装」。当前处理：`apt-get download nmap nmap-common libssh2-1t64 liblinear4 liblua5.4-0 libpcap0.8t64 libblas3 libgfortran5 libquadmath0`，`dpkg-deb -x` 解包至 `~/opt/nmap`，包装脚本 `~/.local/bin/nmap` 设 LD_LIBRARY_PATH 与 --datadir。**建议改用 `sudo apt install -y nmap`**，否则 cron 环境必须显式指定 PATH。

文档第 5 步预测的 `ensurepip is not available` 确实出现，但服务器无 sudo 装不了 `python3.12-venv`，实际改用 `python3 -m venv --without-pip` 加 `python3 -m pip --python <venv解释器> install` 绕行。
