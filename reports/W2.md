## 三、卡最久的一件事

**现象**：跑完 `sudo mysql_secure_installation`，脚本打印 `All done!`，但查 `select user,host,plugin from mysql.user` 时 root 的 plugin 是 `mysql_native_password`，`sudo mysql` 不带密码直接进得去，数据库等于没有密码。

**当时先查的**：没查。七问一路往下按，没逐条读提示，跑完才回头核对 plugin 字段，等于把问题留到了验证阶段才发现。

**根因**：unix_socket 与 root 密码是两个互斥选项。前一步已经把 root 交给 unix_socket 认证，第 3 问「Change the root password?」再答 `Y`，就是在用密码插件覆盖它。脚本自己在提示里写了「root 已受保护，可以安全地答 n」，这句被跳过了。

**处置**：`sudo mysql -e "alter user 'root'@'localhost' identified via unix_socket; flush privileges;"`，再查 plugin 确认回到 `unix_socket`。

**第二件卡住的事**：写 `db.php` 之后 `curl http://127.0.0.1/db.php` 返回 0 字节，不报错也不出内容。当时第一反应是怀疑 nginx 或 PHP 没接上，其实链路是通的——文件本身是空的，PHP 执行了但没有任何输出。

**留下的规矩**：验收看字段取值，不看脚本打印的成功提示；页面空白先确认文件有没有内容，再怀疑链路。
