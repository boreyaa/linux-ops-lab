
# W4 周报 · 2026-11-10 ~ 11-16
阶段一 · 第 4 周 · 网络排查与自动化

## 一、这周做了什么
- 地址、路由和连通性：ip a 看本机地址，ip route 看默认网关，ping 判连通，traceroute 看链路在哪一跳断。
- 抓包：tcpdump 抓指定端口，确认请求到底有没有发出去，区分本机没发还是对端没回。
- 连接状态：ss -lntp 看谁在监听，ss -tnp 看已建立的连接，判断问题在本端还是对端。
- 写巡检脚本：curl 取 HTTP 状态码，if 判断，用 exit 0 或 1 表达结果。
- 挂定时任务：crontab 每 5 分钟执行一次巡检，结果写入日志文件。
- 周六总验收：从一台已有环境的机器重建 nginx 运维闭环，普通用户加 sudo 白名单、8080 站点、巡检脚本、定时任务，逐项验证。

## 二、卡在哪
- 改 /etc/nginx/sites-available/default 的端口完全不生效，nginx -T 里显示的还是 listen 80。
- 软链接建好之后 nginx -t 报 No such file or directory，链接是断的。
- 巡检任务挂到 test1 名下后，日志一行没多，任务看着在跑其实没记录。
- test1 执行 sudo systemctl restart nginx 弹出 polkit 认证，要求输入 bore 的密码。

## 三、怎么解的
- 配置不生效：先 ls -l /etc/nginx/sites-enabled/ 看谁被启用，结果只有 app.conf，default 早被删掉；再用 nginx -T 看最终加载的是哪份文件。改的文件不在加载清单里，改多少遍都不会生效。
- 链接断裂：cat 写的文件名是 site，ln -s 指向的是 site.conf，差一个后缀。ln 建链接时不校验目标是否存在，错误延后到 nginx 读配置时才爆出来。mv 改名后通过。
- 日志不写：ls -l 看到日志文件属主是 root，test1 没有写权限。任务改挂到 root 的 crontab 后恢复正常，日志按五分钟一条累积。
- polkit：尚未解决。sudo 的 NOPASSWD 管得住 sudo 这一层，管不住 systemd 通过 D-Bus 发起的授权检查。

## 阶段总结

四周下来，我能在一台裸机上独立搭起跑在非标准端口的 Web 服务：装系统、配固定 IP、建最小权限账号、装 nginx 与数据库、配站点、写巡检脚本、挂定时任务。遇到「改了没反应」这类问题，我知道先查生效链路，而不是重装。
